# FAST VIDEO CREATOR VERSION 2 — PRIMARY OPERATING RULES

These Version 2 rules govern the fastest safe path for **new** Jmjmcreatzvidz productions. Follow the existing identity, rights, sound, and non-destructive safeguards later in this file. They do not change earlier completed projects.

## Objective
Juan Martinez submits one idea, song, or already-produced Talking Photos MP4. The agent should produce a ready-for-review, saved cinematic edit with as few interruptions as possible. GitHub is an instruction playbook; video generation and editing still require the authorized app/browser, and processing speed or one-click integration is not guaranteed.

## Single brief and single routine approval
- First read the user's current brief and repository, and use already answered details. Produce ONE compact plan including: project name, story and source assets, intended runtime/aspect ratio, visual progression, voice/audio handling, max NEW renders/retakes, and costs/limits.
- Ask once for consent to proceed with that concrete production budget and editing plan. After approval execute routine asset verification, storyboard adjustments, reuse, generation, arranging, muted B-roll, gap checks, and saving without asking for a new permission for every clip.
- New purchases, subscriptions, external uploads, publication, unexpected materially changed story, voice/face substitutions, substantial budget overruns, destructive edits, or newly discovered paid operations ALWAYS require fresh authorization.
- When user has already approved the plan and budget in the current conversation, do not ask again unless constraints materially change.

## Source-of-truth and preflight checklist (execute ONCE, retry only upon new problem)
1. Find the correct saved VideoExpress project or create a NEW project/copy. Use the user's exact name; never choose an unrelated similarly named video. If working on an existing project, save a separate working copy/checkpoint BEFORE destructive changes.
2. Verify source media in the *VideoExpress editor*, not merely Library filename: approved Talking Photos MP4 is visible/audible where playback is available, same face and uninterrupted audio; complete original music MP3 is recognized with correct duration and preview if accessible. Check song offset = end of intro. Distinguish media-library existence from linked timeline clips.
3. If "DELETED" or "1 media file is unavailable" appears, reopen/recheck once: the prior project experienced a stale warning. If it persists or a referenced clip truly fails, STOP and identify it. Do NOT silently ignore or delete media.
4. Cloud browser file-picker limitations: file chooser may not open, or show 0 bytes + "Server responded with 0 code." Do not loop uploads. Ask Juan to upload the specific missing file once in his local Chrome VideoExpress session, then resume at checkpoint and verify. Do not tell him to rebuild a timeline.
5. Preview or verify existing sunrise vehicle, worker-in-scrubs, editing desk, mountains/roads, night sky and other useful clips; only use them when actually present and suitable. A named clip or thumbnail without preview is not verified.
6. Confirm version labels are not payment units: "3.5" is the VideoExpress version, not a verified per-clip price. All Access plan historically stated included AI clips, but never assume remaining allowance is available. Before generation check for *current* paywall, quota, and sharing settings. Keep "Share this in the public gallery" OFF.

## Editing engine
- Convert user-provided script/lyrics into a scene ledger organized by emotional arc. Do not claim second-exact lyric alignment if you cannot hear/inspect audio. Timing estimates remain provisional.
- Prefer REUSE-FIRST: inventory previously approved clips and select nonrepetitive footage; render only missing shots. For music, the completed successful reference used 18 contiguous cutaways, of which 17 were reused and only 1 newly generated. This is a precedent, not a fixed target.
- For NEW voice content, approved stable image, attire, setting, and voice must be referenced. A previously recorded speaker performance cannot be repurposed to say new words while keeping identical mouth performance. A reusable voice is only "locked" when a verified setting/sample exists. Use a short voice test and get approval when needed.
- For approved existing narration: preserve full recorded speaker MP4 with original audio/lip-sync. For a full music video: keep entire master intro unchanged then complete original song unchanged and uninterrupted; move music start to exact intro endpoint. Do not overlap vocals and narration. Preserve silent ending when user requires full original file.
- Place contiguous visuals over the song; choose sequence lengths appropriate to source clips, use muted supporting video tracks, and preview composition. The physical track *number* does NOT determine compositing behavior without inspection.
- Verify 00:00, intro/song changeover, middle, last shot and true final frame. Avoid black gaps *inside* content; black at the timeline endpoint can be normal. Check every clip boundary programmatically where editor supports it; if not, say sampling was partial.
- Save editable Production Copy as "<Project Title> — Production Copy" (or user's supplied name), leaving source/original and Test #3/#4 untouched. Do not overwrite unrelated projects.

## Efficient batch execution
- After one approval, generate and place clips in organized batches, verifying output and count as you proceed. Track `source reusable clips`, `new renders`, `retakes`, `duration covered`, and `remaining gaps`. This ledger avoids lost sessions, duplication and rework.
- If the browser session interrupts, open saved copy and resume only missing segments; do NOT regenerate finished clips and do NOT restart project unless repair is impossible.
- Stop on payment prompts, quota depletion, blocked media, unexpected nonfunctional tools, or inability to meet approved voice/identity requirements. Otherwise keep going through saved edit without repeated check-ins.

## Output and final review
- After assembly: report succinctly in one message: project/copy name, audio integrity checks, clip counts used vs budget, timeline coverage, unresolved errors, preview QA and one next action. Await requested approval before export when the user limited approval to generation/assembly.
- When export was authorized, use an available FullHD 1080p MP4 option without additional purchases, verify download-ready status, and distinguish app success from independently checked final audio/visual export.
- Never publish/share publicly without explicit approval. Public gallery setting OFF.

# Jmjmcreatzvidz — Talking Photos Spokesperson Video Enhancer

Adapted from the ai-playbooks Historical Documentary Video Workflow:
https://github.com/ai-playbooks/historical-documentary-video-workflow

## Purpose

Create a NEW professionally edited VideoExpress video around an EXISTING,
already-speaking Talking Photos MP4 supplied or selected by the customer.
The input video is the authoritative source for the speaker's identity, facial
performance, complete dialogue, embedded audio, timing, and lip-sync. Preserve it.
Use VideoExpress for supporting footage, scene changes, cutaways, screen captures,
animations, framing, transitions and final assembly. GitHub holds instructions,
NOT media files and NOT a video timeline or video-generation engine.

This is an enhancement/compositing workflow, NOT a request to recreate the
Talking Photos character, synthesize a new voice, or retell its spoken script.
The format can be educational, promotional, motivational, humorous, musical,
or documentary: it is NOT restricted to history.

## First interaction

If already supplied, use the customer's inputs without repeating questions.
Otherwise ask only for:
- Which EXISTING, authorized Talking Photos video to use (upload/file or
  identified asset in VideoExpress media library).
- What new supporting scenes, topic/style, and output format are wanted.
For a basic test use one short spokesperson video, one or two supporting visual
cutaways, and the source clip's natural duration. Prefer vertical 9:16 for shorts
only when the user wants that format. Preserve the customer's approved branding:
Jmjmcreatzvidz (exact spelling).

## Critical safety and source-lock rules

1. Preserve the speaker's original face, body, speech, audio, and lip-sync.
   No generated replacement character, no cloned voice, no TTS, no resynthesis,
   no script rewriting, and no added spoken words without separate authorization.
2. Import the completed MP4 as a normal video WITH its original embedded audio.
   Do not mistake an image/photo or a generated reference for the full speaking MP4.
3. Keep an untouched original VideoExpress project and save edits as a separately
   named copy. Do not delete existing assets or overwrite Test #3.
4. No payments, extra subscriptions, posting, external service uploads, or
   public gallery sharing without explicit customer approval.
5. Do not assume browser tools, buttons, audio playback access, or account
   entitlements. Verify supported controls in the signed-in application.
6. Work within the user's approved generation/processing budget; check for
   existing queued jobs before resubmitting.

## Editing strategy — Paul's talking-video + supporting visuals approach

The complete Talking Photos performance provides the MAIN SPEECH/AUDIO TRACK.
It does NOT have to become a transparent cutout to produce a polished video.
Prefer straightforward sequence editing with speaker footage, visual cutaways,
picture-in-picture if supported, split-screen, text, graphics and screen captures.
Keep the original person's voice playing underneath illustrative cutaways.

Avoid the unsuccessful assumption that green-screen will automatically isolate
a speaking person filmed against a detailed varied background. VideoExpress's
tested chroma key controls (sampled color, Similarity, Blend) did not cleanly
remove the background in this customer's MP4: the hair/face developed holes.
Do NOT retry it as the default method. Transparent-person compositing is OPTIONAL
and only when a tested compatible transparent source and alpha workflow exist.

## Browser production steps

A. INSPECT
   - Open https://app.videoexpress.ai in the authorized signed-in editor.
   - Locate the already-uploaded master in Media Library > My Media, or upload
     it with authorization. Confirm filename and preview, not thumbnail only.
   - Confirm clip runs from beginning to end and plays its ORIGINAL voice with
     synchronized mouth movements. If audio is missing or altered, STOP.
   - Inspect timeline/track order in the actual UI; do not assume which numbered
     track sits visually above another.

B. PRESERVE
   - Create a NEW named project or saved copy: "Jmjmcreatzvidz — <topic> — Edit".
   - Insert the master once at 00:00. Keep its image and embedded audio aligned.
   - Save before edits. The original is never overwritten.

C. PLAN
   - Map the existing spoken performance into natural segments by listening
     when possible. Do not invent transcript words or claim transcription
     was verified if no audio-listening capability is available.
   - Plan supporting B-roll/cutaways to match the ACTUAL speech, such as
     mountain scenery for a Colorado story, relevant on-screen app footage
     for a software tutorial, or appropriate illustrations for narration.
   - Prefer few purposeful visual changes rather than random effects. When
     speaker must remain visible, use split-screen/PIP only if supported.
   - Keep the already recorded audio as the one uninterrupted voice source.

D. GENERATE/IMPORT SUPPORTING VIDEO ONLY
   - Use existing authorized media or VideoExpress generation for backgrounds,
     illustrations and cutaways, NOT a replacement talking character.
   - Keep source media / purchased rights and production scope documented.
   - Assemble cutaway visuals on appropriate additional tracks or in the
     speaker's visual sequence. Mute any new clip's speech/sound if it would
     conflict with the original voice.
   - Check synchronization carefully before and after cuts. Never duplicate
     the original voice or create gaps in it. Never allow a background video
     to completely hide the moving speaker when the user specifically wants
     them visible, unless that cutaway was requested.
   - Avoid overly large zooms or cropping the mouth.

E. TITLES, CAPTIONS, EFFECTS
   - Use only controls that expose reliably previewable text and placement.
     VideoExpress automatic captions may open separate VidSubtitle service:
     do NOT upload to it without the user's explicit permission.
   - The customer's prior tests found the lower-third Text Animations
     templates previewed blank and Filters > Titles lacked usable standalone
     text entry. If still unsupported, leave title unapplied and report the
     limitation; do not waste repeated cycles or submit unreadable text.
   - Brand credit, when requested: "Created by Jmjmcreatzvidz".
   - Subtle animation should not affect original speech timing.

F. REVIEW, SAVE, EXPORT
   - Rewatch beginning, middle and end in the editor where supported;
     confirm same face/voice, no repeated or skipped dialogue, lip-sync,
     no audio duplication, and supporting scene order.
   - Save to the NEW project. Export MP4 at available resolution (prefer
     1080p if available without new charges). Download if supported.
   - Verify actual output playback and its original voice/lip-sync. Clearly
     mark anything not directly verified as UNVERIFIED.
   - Preserve source media, successful clips, and both saved projects.

## NEW PRIMARY MODE — THOUGHTS TO COMPLETE CINEMATIC VIDEO

When Juan shares an idea in his own words ("I'm thinking about..."), this is the desired end-to-end workflow:

1. **Interpret idea without changing his core meaning.** Draft a short natural first-person script using his name only when appropriate. Ask about missing essentials only; for a short default use ~45–60 seconds, 16:9 unless the requested outlet is shorts/reels, then 9:16. Do not turn emotional/confessional thoughts into exaggerated marketing claims.
2. **Share for approval.** Provide the exact spoken script, duration estimate, proposed story arc, and scene-by-scene visual plan. Ask for one approval before spending credits or generating voice/video.
3. **Identify master reference.** Locate user's supplied approved cinematic spokesperson master image and a playable approved voice sample/profile in the user's authorized app workspace. Stop and ask for the actual file if unavailable. Do not infer access from GitHub instructions.
4. **Talking Photos voice/animation test.** For NEW script, first test a short representative sample using approved master image, best available reusable voice setting, low-baritone subtle Mexican American English description. Check facial identity, sunglasses/cap/outfit, voice register/accent, speech intelligibility and lip sync. If reusable voice lock cannot be confirmed, report limitation and request user approval of the sample. Do not automatically resubmit/recreate repeatedly.
5. **Produce complete spokesperson performance** with the approved new script and approved voice setting. Keep one recorded voice/audio performance master for the whole video. Verify its beginning/end, duration and embedded sound if possible.
6. **Build VideoExpress cinematic production.** Create a separately named new project; import the completed speaking MP4 with its audio. Build scene-by-scene supporting clips/illustrations/B-roll, ideally 3–6 scenes for ~45–60 seconds, in the requested ratio. Align scenes to the script ledger, using full-screen cutaways, split-screen or picture-in-picture where genuinely supported. Use actual VideoExpress track compositing behavior verified via preview/output, not assumptions from track numbers. Keep original master narration continuous and avoid B-roll audio clashing.
7. **Polish, save, export.** Use subtle transitions, optional low-background music only if it doesn't overpower the speaker and is authorized, and captions if functionality is accessible and independently previewable. Preserve an untouched source and save an editable copy. Export a separate MP4; review actual output at beginning, cutaway points and ending. Do not post/share without approval.
8. **Report honestly.** Note whether speaker appearance, voice identity, lip sync, duration, cutaways, music, captions, export were tested or are unverified; include single clear next step.

Never hallucinate a verified transcript from a muted/unavailable player. If the user gives an approximate topic rather than exact transcript, label timing provisional.
