# Jmjmcreatzvidz — Talking Photos Spokesperson Video Enhancer

Adapted from the ai-playbooks Historical Documentary Video Workflow:
https://github.com/ai-playbooks/historical-documentary-video-workflow

## Purpose

Create a NEW professionally edited VideoExpress video around an EXISTING,
already-speaking Talking Photos MP4 supplied or selected by the customer.
The input video is the authoritative source for the speaker's identity, facial
performance, complete dialogue, embedded audio, timing, and lip-sync. Preserve it.
Use VideoExpress for supporting footage, scene changes, cutaways, screen captures,
animations, framing, transitions and final assembly. GitHub holds instructions,
NOT media files and NOT a video timeline or video-generation engine.

This is an enhancement/compositing workflow, NOT a request to recreate the
Talking Photos character, synthesize a new voice, or retell its spoken script.
The format can be educational, promotional, motivational, humorous, musical,
or documentary: it is NOT restricted to history.

## First interaction

If already supplied, use the customer's inputs without repeating questions.
Otherwise ask only for:
- Which EXISTING, authorized Talking Photos video to use (upload/file or
  identified asset in VideoExpress media library).
- What new supporting scenes, topic/style, and output format are wanted.
For a basic test use one short spokesperson video, one or two supporting visual
cutaways, and the source clip's natural duration. Prefer vertical 9:16 for shorts
only when the user wants that format. Preserve the customer's approved branding:
Jmjmcreatzvidz (exact spelling).

## Critical safety and source-lock rules

1. Preserve the speaker's original face, body, speech, audio, and lip-sync.
   No generated replacement character, no cloned voice, no TTS, no resynthesis,
   no script rewriting, and no added spoken words without separate authorization.
2. Import the completed MP4 as a normal video WITH its original embedded audio.
   Do not mistake an image/photo or a generated reference for the full speaking MP4.
3. Keep an untouched original VideoExpress project and save edits as a separately
   named copy. Do not delete existing assets or overwrite Test #3.
4. No payments, extra subscriptions, posting, external service uploads, or
   public gallery sharing without explicit customer approval.
5. Do not assume browser tools, buttons, audio playback access, or account
   entitlements. Verify supported controls in the signed-in application.
6. Work within the user's approved generation/processing budget; check for
   existing queued jobs before resubmitting.

## Editing strategy — Paul's talking-video + supporting visuals approach

The complete Talking Photos performance provides the MAIN SPEECH/AUDIO TRACK.
It does NOT have to become a transparent cutout to produce a polished video.
Prefer straightforward sequence editing with speaker footage, visual cutaways,
picture-in-picture if supported, split-screen, text, graphics and screen captures.
Keep the original person's voice playing underneath illustrative cutaways.

Avoid the unsuccessful assumption that green-screen will automatically isolate
a speaking person filmed against a detailed varied background. VideoExpress's
tested chroma key controls (sampled color, Similarity, Blend) did not cleanly
remove the background in this customer's MP4: the hair/face developed holes.
Do NOT retry it as the default method. Transparent-person compositing is OPTIONAL
and only when a tested compatible transparent source and alpha workflow exist.

## Browser production steps

A. INSPECT
   - Open https://app.videoexpress.ai in the authorized signed-in editor.
   - Locate the already-uploaded master in Media Library > My Media, or upload
     it with authorization. Confirm filename and preview, not thumbnail only.
   - Confirm clip runs from beginning to end and plays its ORIGINAL voice with
     synchronized mouth movements. If audio is missing or altered, STOP.
   - Inspect timeline/track order in the actual UI; do not assume which numbered
     track sits visually above another.

B. PRESERVE
   - Create a NEW named project or saved copy: "Jmjmcreatzvidz — <topic> — Edit".
   - Insert the master once at 00:00. Keep its image and embedded audio aligned.
   - Save before edits. The original is never overwritten.

C. PLAN
   - Map the existing spoken performance into natural segments by listening
     when possible. Do not invent transcript words or claim transcription
     was verified if no audio-listening capability is available.
   - Plan supporting B-roll/cutaways to match the ACTUAL speech, such as
     mountain scenery for a Colorado story, relevant on-screen app footage
     for a software tutorial, or appropriate illustrations for narration.
   - Prefer few purposeful visual changes rather than random effects. When
     speaker must remain visible, use split-screen/PIP only if supported.
   - Keep the already recorded audio as the one uninterrupted voice source.

D. GENERATE/IMPORT SUPPORTING VIDEO ONLY
   - Use existing authorized media or VideoExpress generation for backgrounds,
     illustrations and cutaways, NOT a replacement talking character.
   - Keep source media / purchased rights and production scope documented.
   - Assemble cutaway visuals on appropriate additional tracks or in the
     speaker's visual sequence. Mute any new clip's speech/sound if it would
     conflict with the original voice.
   - Check synchronization carefully before and after cuts. Never duplicate
     the original voice or create gaps in it. Never allow a background video
     to completely hide the moving speaker when the user specifically wants
     them visible, unless that cutaway was requested.
   - Avoid overly large zooms or cropping the mouth.

E. TITLES, CAPTIONS, EFFECTS
   - Use only controls that expose reliably previewable text and placement.
     VideoExpress automatic captions may open separate VidSubtitle service:
     do NOT upload to it without the user's explicit permission.
   - The customer's prior tests found the lower-third Text Animations
     templates previewed blank and Filters > Titles lacked usable standalone
     text entry. If still unsupported, leave title unapplied and report the
     limitation; do not waste repeated cycles or submit unreadable text.
   - Brand credit, when requested: "Created by Jmjmcreatzvidz".
   - Subtle animation should not affect original speech timing.

F. REVIEW, SAVE, EXPORT
   - Rewatch beginning, middle and end in the editor where supported;
     confirm same face/voice, no repeated or skipped dialogue, lip-sync,
     no audio duplication, and supporting scene order.
   - Save to the NEW project. Export MP4 at available resolution (prefer
     1080p if available without new charges). Download if supported.
   - Verify actual output playback and its original voice/lip-sync. Clearly
     mark anything not directly verified as UNVERIFIED.
   - Preserve source media, successful clips, and both saved projects.

## Reporting

Report: input master asset identified; existing project preserved; new project
name; supporting visuals created/inserted; source audio preserved or blocked;
actual export/download outcome; visual/audio checks actually completed;
limitations and exactly one next action.

## How this differs from the original historical documentary playbook

We reuse the useful idea of combining an established presenter with
story-supporting scenes. We DO NOT use the original fictional presenter,
CloneVoice narrator, compulsory watercolor art style, minimum-length intro,
or built-in scene generation for the spokesperson. The speaker comes from
the customer's finished Talking Photos MP4 throughout.

## Known, customer-verified baseline

In VideoExpress Test #3, the user's existing Talking Photos MP4 was uploaded,
put on the timeline, played with the correct original voice and lip-sync,
saved, and exported successfully. A later saved copy retained the original
master clip and added a subtle zoom. Green-screen removal was not usable
for isolating the speaker. Template titles failed trustworthy preview.
These observations establish a practical starting point, not a guarantee
for every future input or software version.
